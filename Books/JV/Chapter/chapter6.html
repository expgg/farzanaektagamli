অধ্যায় ৬: জাভা ডাটাবেজ সংযোগ (JDBC)

অতি সংক্ষিপ্ত প্রশ্ন

১। জাভা ডাটাবেজ কানেকটিভিটি (JDBC) বলতে কী বুঝায়?

পরীক্ষায় লেখার জন্য: JDBC হলো একটি Java API যা জাভা প্রোগ্রামকে বিভিন্ন ধরনের ডাটাবেজের সাথে সংযোগ স্থাপন এবং ডেটা আদান-প্রদানের সুযোগ করে দেয়।

সহজ ভাষায় ব্যাখ্যা: JDBC হলো জাভা আর ডাটাবেজের মধ্যে কথা বলার একটা মাধ্যম বা ব্রিজ। এটার সাহায্যে রিফাত তার জাভা কোড দিয়ে ডাটাবেজে কানেক্ট করতে পারে, ডেটা ঢোকাতে পারে, ডেটা বের করতে পারে বা ডেটা বদলাতে পারে।

একদম সহজ ব্যাখ্যা: JDBC হলো একটা দোভাষী, যে জাভার কথা ডাটাবেজকে আর ডাটাবেজের কথা জাভাকে বুঝিয়ে দেয়।

২। কানেকশন কী?

পরীক্ষায় লেখার জন্য: ডাটাবেজের সাথে একটি সক্রিয় সংযোগ বা সেশন।

সহজ ভাষায় ব্যাখ্যা: Connection হলো জাভা প্রোগ্রামের সাথে ডাটাবেজের একটা লাইভ লিংক বা যোগাযোগ স্থাপন। এই লিংক তৈরি হলেই তুমি ডাটাবেজে ডেটা পাঠানো বা নিয়ে আসার কাজগুলো করতে পারবে।

একদম সহজ ব্যাখ্যা: ডাটাবেজের সাথে তোমার প্রোগ্রামের একটা ফোন কল চালু হওয়াটাই হলো কানেকশন।

৩। স্টেটমেন্ট বলতে কী বুঝায়?

পরীক্ষায় লেখার জন্য: ডাটাবেজে SQL কোয়েরি পাঠানোর একটি অবজেক্ট বা ইন্টারফেস।

সহজ ভাষায় ব্যাখ্যা: Statement হলো JDBC এর একটা অংশ যা ব্যবহার করে তুমি ডাটাবেজের উপর SQL কমান্ড (যেমন: ডেটা খোঁজা, ঢোকানো, মোছা) চালাতে পারো। কানেকশন পাওয়ার পর স্টেটমেন্ট তৈরি করে তার মাধ্যমে কমান্ড পাঠাতে হয়।

একদম সহজ ব্যাখ্যা: ডাটাবেজকে প্রশ্ন করার বা আদেশ দেওয়ার জন্য একটা ফর্ম বা কাগজ হলো স্টেটমেন্ট।

৪। প্রিপেয়ার্ড স্টেটমেন্ট ব্যবহার করা হয় কেন?

পরীক্ষায় লেখার জন্য: পারফরম্যান্স বৃদ্ধি এবং SQL ইনজেকশন অ্যাটাক প্রতিরোধের জন্য।

সহজ ভাষায় ব্যাখ্যা: Prepared Statement হলো Statement এর একটা উন্নত ভার্সন। এটা একই SQL কমান্ড বারবার চালানোর জন্য খুব ফাস্ট এবং নিরাপদ। কারণ কমান্ডটা আগে থেকেই ডাটাবেজে কম্পাইল করা থাকে এবং বাইরের ডেটা সরাসরি কমান্ডের অংশ হতে পারে না, ফলে হ্যাকিং (SQL Injection) এর ঝুঁকি কমে যায়।

একদম সহজ ব্যাখ্যা: মনে করো তুমি ফারজানাকে প্রতিদিন একই প্রশ্ন করো, শুধু নামটা বদলাও। Prepared Statement হলো প্রশ্নটা একবার লিখে শুধু নাম বসানোর জায়গাটা খালি রাখা। এতে প্রতিবার পুরো প্রশ্ন লিখতে হয় না, কাজ দ্রুত হয় আর কেউ ভুল নাম বসিয়ে সমস্যা করতে পারে না।

৫। JDBC ড্রাইভার বলতে কী বুঝায়?

পরীক্ষায় লেখার জন্য: জাভা অ্যাপ্লিকেশন এবং নির্দিষ্ট ডাটাবেজের মধ্যে সংযোগ স্থাপনকারী একটি সফটওয়্যার কম্পোনেন্ট বা লাইব্রেরি।

সহজ ভাষায় ব্যাখ্যা: প্রত্যেক ডাটাবেজের (যেমন MySQL, Oracle, PostgreSQL) সাথে জাভার কথা বলার নিজস্ব নিয়ম আছে। JDBC ড্রাইভার হলো সেই সফটওয়্যার যা নির্দিষ্ট একটা ডাটাবেজের নিয়ম অনুযায়ী জাভা অ্যাপ্লিকেশনের সাথে ওই ডাটাবেজের যোগাযোগ করিয়ে দেয়।

একদম সহজ ব্যাখ্যা: তোমার যেমন বিভিন্ন দেশের মানুষের সাথে কথা বলতে ভিন্ন ভিন্ন দোভাষী লাগে, তেমনি জাভারও ভিন্ন ভিন্ন ডাটাবেজের সাথে কথা বলতে ভিন্ন ভিন্ন JDBC ড্রাইভার লাগে।

৬। ODBC-এর কাজ কী?

পরীক্ষায় লেখার জন্য: বিভিন্ন অ্যাপ্লিকেশনের জন্য ডাটাবেজ অ্যাক্সেসের একটি স্ট্যান্ডার্ড ইন্টারফেস বা API প্রদান করা।

সহজ ভাষায় ব্যাখ্যা: ODBC (Open Database Connectivity) হলো ডাটাবেজের সাথে কানেক্ট করার একটা সাধারণ নিয়ম বা স্ট্যান্ডার্ড। JDBC যেমন শুধু জাভার জন্য, ODBC অনেক ধরণের প্রোগ্রামিং ল্যাঙ্গুয়েজ থেকেই ব্যবহার করা যায়। JDBC-ODBC Bridge ড্রাইভার ব্যবহার করে জাভা থেকেও ODBC এর মাধ্যমে ডাটাবেজে কানেক্ট করা যেত (যদিও এখন এটা কম ব্যবহৃত)।

একদম সহজ ব্যাখ্যা: ODBC হলো একটা মাস্টার-কি বা অ্যাডাপ্টার, যা দিয়ে অনেক ধরণের তালা (ডাটাবেজ) খোলা যায়।

৭। নেটওয়ার্ক প্রটোকল ড্রাইভার কী?

পরীক্ষায় লেখার জন্য: একটি JDBC ড্রাইভার যা নির্দিষ্ট ডাটাবেজের নেটওয়ার্ক প্রটোকল ব্যবহার করে সরাসরি ডাটাবেজ সার্ভারের সাথে যোগাযোগ করে।

সহজ ভাষায় ব্যাখ্যা: এটা এক ধরণের JDBC ড্রাইভার (Type 4 ড্রাইভার)। এটা জাভা কোডকে সরাসরি নেটওয়ার্কের মাধ্যমে ডাটাবেজ সার্ভারের সাথে কথা বলতে সাহায্য করে। এর জন্য ক্লায়েন্ট মেশিনে অন্য কোনো সফটওয়্যার লাগে না, শুধু এই ড্রাইভারটাই যথেষ্ট। এটা সাধারণত সবচেয়ে ফাস্ট এবং জনপ্রিয় উপায়।

একদম সহজ ব্যাখ্যা: এই ড্রাইভারটা হলো সরাসরি ডাটাবেজের সাথে কথা বলার হটলাইন ফোন নাম্বার। অন্য কোনো মাধ্যম লাগে না।

৮। JDBC স্টেটমেন্ট কত প্রকার ও কী কী?

পরীক্ষায় লেখার জন্য: প্রধানত ৩ প্রকার: `Statement`, `PreparedStatement`, `CallableStatement`।

সহজ ভাষায় ব্যাখ্যা: JDBC তে SQL কমান্ড পাঠানোর জন্য মূলত তিন ধরনের স্টেটমেন্ট আছে:

  1. `Statement`: সাধারণ SQL কমান্ড চালানোর জন্য।
  2. `PreparedStatement`: একই কমান্ড বারবার চালানোর জন্য (পারফরম্যান্স ভালো, নিরাপদ)।
  3. `CallableStatement`: ডাটাবেজের স্টোরড প্রসিডিউর (Stored Procedure) কল করার জন্য।

একদম সহজ ব্যাখ্যা: ডাটাবেজকে আদেশ দেওয়ার ৩ রকম ফর্ম: ১) সাধারণ ফর্ম (`Statement`), ২) পূরণ করা সহজ ফর্ম (`PreparedStatement`), ৩) বিশেষ কাজের জন্য ফর্ম (`CallableStatement`)।

সংক্ষিপ্ত প্রশ্ন

১। JDBC ব্যবহারের সুবিধাসমূহ উল্লেখ কর।

পরীক্ষায় লেখার জন্য:

  • ডাটাবেজ স্বাধীনতা (Database Independence): একই JDBC API ব্যবহার করে বিভিন্ন বিক্রেতার ডাটাবেজের সাথে কাজ করা যায়, কোড সামান্য পরিবর্তন করে বা না করেই।
  • প্ল্যাটফর্ম স্বাধীনতা (Platform Independence): জাভার মতো JDBC ও প্ল্যাটফর্ম নির্ভর নয়, যেকোনো অপারেটিং সিস্টেমে চলে।
  • সহজ ব্যবহার: JDBC API তুলনামূলকভাবে সহজবোধ্য এবং ব্যবহার করা সহজ।
  • পারফরম্যান্স: Type 4 ড্রাইভার ব্যবহার করলে ভালো পারফরম্যান্স পাওয়া যায়।
  • SQL স্ট্যান্ডার্ড সমর্থন: স্ট্যান্ডার্ড SQL কোয়েরি ব্যবহার করা যায়।
  • ব্যতিক্রম হ্যান্ডলিং: `SQLException` এর মাধ্যমে ডাটাবেজ সম্পর্কিত ত্রুটি সহজে হ্যান্ডেল করা যায়।
  • বিভিন্ন ড্রাইভার টাইপ: প্রয়োজন অনুযায়ী বিভিন্ন ধরনের JDBC ড্রাইভার (Type 1-4) ব্যবহারের সুযোগ।

সহজ ভাষায় ব্যাখ্যা: JDBC ব্যবহার করলে লাভ হলো:

  • এক ডাটাবেজ থেকে অন্য ডাটাবেজে সুইচ করা সহজ।
  • যেকোনো কম্পিউটারে (Windows, Mac, Linux) চলে।
  • ব্যবহার করা সোজা।
  • ভালো স্পিড পাওয়া যায়।
  • সাধারণ SQL কমান্ড লেখা যায়।
  • ডাটাবেজের ভুলগুলো ধরা ও সামলানো সহজ।

একদম সহজ ব্যাখ্যা: JDBC দোভাষী ব্যবহার করলে সুবিধা: এই দোভাষী অনেক ভাষা জানে (বিভিন্ন ডাটাবেজ), যেকোনো জায়গায় কাজ করে (প্ল্যাটফর্ম), কথা বলা সহজ, তাড়াতাড়ি অনুবাদ করে (পারফরম্যান্স), আর ভুল হলে সেটাও বলে দেয়।

২। ODBC ড্রাইভারের ব্লক ডায়াগ্রাম অঙ্কন কর।

পরীক্ষায় লেখার জন্য:

ব্লক ডায়াগ্রাম (টেক্সট):


    +---------------------+      +---------------------+      +---------------------+      +---------------------+
    | Java Application    | ---> | JDBC-ODBC Bridge    | ---> | ODBC Driver Manager | ---> | ODBC Driver (Vendor)| ---> Database
    | (Using JDBC API)    |      | (Type 1 JDBC Driver)|      | (OS Component)      |      | (e.g., MySQL Driver)|
    +---------------------+      +---------------------+      +---------------------+      +---------------------+

ব্যাখ্যা: এই ডায়াগ্রামে দেখানো হয়েছে কীভাবে একটি জাভা অ্যাপ্লিকেশন JDBC API ব্যবহার করে JDBC-ODBC Bridge ড্রাইভারের মাধ্যমে অপারেটিং সিস্টেমের ODBC Driver Manager এর সাথে যোগাযোগ করে। Driver Manager তখন নির্দিষ্ট ডাটাবেজ বিক্রেতার (Vendor) দেওয়া ODBC Driver ব্যবহার করে ডাটাবেজের সাথে সংযোগ স্থাপন করে। এটি একটি পুরনো পদ্ধতি এবং বর্তমানে কম ব্যবহৃত হয় কারণ এটি একাধিক স্তর পার করায় পারফরম্যান্স কিছুটা কম থাকে এবং ক্লায়েন্ট মেশিনে ODBC কনফিগারেশনের প্রয়োজন হয়।

সহজ ভাষায় ব্যাখ্যা: JDBC-ODBC Bridge হলো একটা বহুস্তর বিশিষ্ট ব্যবস্থা। জাভা প্রোগ্রাম প্রথমে JDBC Bridge কে বলে, Bridge সেটাকে অপারেটিং সিস্টেমের ODBC Manager কে দেয়, Manager আবার নির্দিষ্ট ডাটাবেজের ODBC Driver কে দেয়, তারপর সেই Driver ডাটাবেজের সাথে কথা বলে। অনেকগুলো ধাপ পার হতে হয়।

একদম সহজ ব্যাখ্যা: তুমি -> তোমার বন্ধু রিফাত -> রিফাতের বন্ধু ফারজানা -> ফারজানার ভাই -> আসল লোক। অনেক মাধ্যম ঘুরে ডাটাবেজের কাছে পৌঁছাতে হচ্ছে।

৩। নেটওয়ার্ক প্রটোকল ড্রাইভার সংক্ষেপে বর্ণনা কর।

পরীক্ষায় লেখার জন্য: নেটওয়ার্ক প্রটোকল ড্রাইভার, যা Type 4 JDBC ড্রাইভার নামেও পরিচিত, সম্পূর্ণরূপে জাভাতে লেখা একটি ড্রাইভার। এটি ডাটাবেজের নিজস্ব নেটওয়ার্কিং প্রটোকল ব্যবহার করে সরাসরি ডাটাবেজ সার্ভারের সাথে কমিউনিকেট করে। এর জন্য ক্লায়েন্ট মেশিনে কোনো অতিরিক্ত ডাটাবেজ-স্পেসিফিক লাইব্রেরি বা সফটওয়্যার ইনস্টল করার প্রয়োজন হয় না, শুধুমাত্র ড্রাইভারের JAR ফাইলটিই যথেষ্ট। এটি প্ল্যাটফর্ম-স্বাধীন এবং সাধারণত সবচেয়ে ভালো পারফরম্যান্স প্রদান করে বলে বহুলভাবে ব্যবহৃত হয়।

সহজ ভাষায় ব্যাখ্যা: Type 4 বা নেটওয়ার্ক প্রটোকল ড্রাইভার হলো সবচেয়ে আধুনিক আর কাজের JDBC ড্রাইভার। এটা পিওর জাভাতে তৈরি আর সরাসরি নেটওয়ার্ক দিয়ে ডাটাবেজের সাথে কথা বলে। তোমার কম্পিউটারে শুধু এই ড্রাইভারের `.jar` ফাইলটা থাকলেই চলে, আর কিছু ইনস্টল দিতে হয় না। এটা ফাস্ট আর যেকোনো অপারেটিং সিস্টেমে কাজ করে।

একদম সহজ ব্যাখ্যা: এটা হলো ডাটাবেজের সাথে কথা বলার জন্য একটা স্মার্টফোন অ্যাপ (Type 4 Driver)। অ্যাপটা থাকলেই তুমি সরাসরি ডাটাবেজকে কল (নেটওয়ার্ক কানেকশন) করতে পারো, অন্য কোনো টেলিফোন অপারেটর বা লাইনের দরকার হয় না।

৪। প্রিপেয়ার্ড স্টেটমেন্টের সুবিধাসমূহ উল্লেখ কর।

পরীক্ষায় লেখার জন্য:

  • পারফরম্যান্স: একই SQL কোয়েরি ভিন্ন ভিন্ন প্যারামিটার দিয়ে বারবার এক্সিকিউট করার ক্ষেত্রে `PreparedStatement` অনেক দ্রুত কাজ করে, কারণ কোয়েরিটি ডাটাবেজে একবারই প্রি-কম্পাইলড হয়।
  • SQL ইনজেকশন প্রতিরোধ: এটি প্যারামিটারাইজড কোয়েরি সমর্থন করে, যেখানে ইনপুট ডেটা SQL কমান্ডের অংশ হিসেবে বিবেচিত না হয়ে শুধুমাত্র ডেটা হিসেবে ব্যবহৃত হয়। এটি SQL ইনজেকশন নামক নিরাপত্তা ঝুঁকি থেকে রক্ষা করে।
  • পঠনযোগ্যতা ও রক্ষণাবেক্ষণ: কোয়েরি থেকে ডেটা আলাদা থাকায় কোড বোঝা ও ম্যানেজ করা সহজ হয়।
  • ব্যাচ আপডেট: একাধিক আপডেট বা ইনসার্ট কমান্ড একসাথে ব্যাচ হিসেবে এক্সিকিউট করার সুবিধা দেয়, যা পারফরম্যান্স বাড়ায়।

সহজ ভাষায় ব্যাখ্যা: `PreparedStatement` ব্যবহারের সুবিধা:

  • একই প্রশ্ন বারবার করলে উত্তর তাড়াতাড়ি পাওয়া যায়।
  • কেউ ভুল বা খারাপ ডেটা দিয়ে সিস্টেম হ্যাক করতে পারে না (SQL Injection হয় না)।
  • কোড দেখতে সুন্দর আর গোছানো লাগে।
  • অনেকগুলো ডেটা একসাথে আপডেট করা যায়।

একদম সহজ ব্যাখ্যা: রেডি করা প্রশ্নপত্র (`PreparedStatement`): ১) একবার প্রশ্ন রেডি করলে বারবার ব্যবহার করা যায়, শুধু ছাত্রের নাম বদলালেই হয় (ফাস্ট)। ২) ছাত্র উত্তরে যা খুশি লিখতে পারে না, শুধু নির্দিষ্ট জায়গায় নাম লিখতে পারে (নিরাপদ)। ৩) প্রশ্নটা দেখতে পরিষ্কার লাগে।

৫। প্রিপেয়ার্ড স্টেটমেন্টসমূহের মেথডগুলো কী কী?

পরীক্ষায় লেখার জন্য: `PreparedStatement` ইন্টারফেসের কিছু গুরুত্বপূর্ণ মেথড হলো:

  • বিভিন্ন `setXxx(int parameterIndex, Xxx value)` মেথড: কোয়েরির প্যারামিটারে (`?` চিহ্নিত স্থানে) মান সেট করার জন্য। যেমন: `setInt()`, `setString()`, `setDouble()`, `setDate()` ইত্যাদি। `parameterIndex` 1 থেকে শুরু হয়।
  • `executeUpdate()`: ডেটা পরিবর্তনকারী SQL কমান্ড (INSERT, UPDATE, DELETE) এক্সিকিউট করার জন্য। কতগুলো রো প্রভাবিত হলো তা রিটার্ন করে।
  • `executeQuery()`: ডেটা রিট্রিভকারী SQL কমান্ড (SELECT) এক্সিকিউট করার জন্য। `ResultSet` অবজেক্ট রিটার্ন করে।
  • `addBatch()`: ব্যাচ এক্সিকিউশনের জন্য বর্তমান প্যারামিটার সেট সহ কমান্ডটি ব্যাচে যোগ করে।
  • `executeBatch()`: ব্যাচে যোগ করা সব কমান্ড একসাথে এক্সিকিউট করে।
  • `clearParameters()`: বর্তমান প্যারামিটার সেট মুছে ফেলে।

সহজ ভাষায় ব্যাখ্যা: `PreparedStatement` এর কিছু কাজের বোতাম (মেথড):

  • `set...()`: খালি জায়গায় (প্রশ্নের `?` গুলোতে) মান বসানো (যেমন: `setString(1, "রিফাত")`)।
  • `executeUpdate()`: ডেটা ঢোকানো, বদলানো বা মোছার কমান্ড চালানো।
  • `executeQuery()`: ডেটা খুঁজে বের করার কমান্ড চালানো।
  • `addBatch()` / `executeBatch()`: অনেকগুলো কমান্ড একসাথে জমা করে চালানো।
  • `clearParameters()`: খালি জায়গার মানগুলো মুছে ফেলা।

একদম সহজ ব্যাখ্যা: পূরণ করার ফর্ম (`PreparedStatement`): `set` (খালি ঘরে লেখা), `executeUpdate` (ফর্ম জমা দেওয়া - ডেটা বদলাতে), `executeQuery` (ফর্ম জমা দেওয়া - তথ্য খুঁজতে), `addBatch` (অনেকগুলো ফর্ম একসাথে পিন করা), `executeBatch` (পিন করা সব ফর্ম একসাথে জমা দেওয়া)।
